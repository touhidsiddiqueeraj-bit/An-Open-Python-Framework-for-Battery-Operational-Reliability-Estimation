Why this matters

Grid batteries are asked: "Can you safely deliver power for the next N hours?"

  • Say yes when the battery is healthy → earn revenue
  • Say yes when it's about to fail → blackout, penalty costs
  • Say no when it would have been fine → lost revenue

Shikdar & Laaksonen (2026) built a machine learning framework to predict failure probability across multiple horizons (10–50 cycles). They reported:

  • AUC = 0.944 on 37 batteries
  • Failure rate reduction: 10.3% → 2.95%

Can we reproduce this with the public NASA dataset that most researchers use?

Our Reproducibility Pipeline

We implemented the entire framework as a modular Python package:

  • Data layer: NASALoader parses .mat files, normalizes features (SOH, voltage, current, temperature)
  • Model layer: XGBoost with per-horizon multi-output classification, isotonic calibration on validation fold
  • Dispatch layer: Threshold policies, derating, Monte Carlo market simulator
  • Evaluation: Leave-one-battery-out CV, AUC/Brier/ECE metrics, per-fold reporting

Single command: python run_all.py --quick — completes in < 10 seconds

Three Hidden Bugs We Found

Bug 1: Calibration Data Leakage

Original code fit the isotonic calibrator on test data — then evaluated on the same data. This inflated AUC from 0.46 to an apparent 0.74. Fix: fit on a held-out validation fold.

Bug 2: Energy Unit Confusion

Revenue = energy (kWh) × price ($/MWh) — without dividing by 1000, revenue was overstated by 1000× ($3,780 vs $3.78).

Bug 3: Inconsistent Baseline Metric

Baseline failure rate used label density across all horizons; model rows used conditional dispatch-based metric. Incomparable.

Takeaways

First quantitative scaling curve for battery ML

AUC vs N curve: N ≤ 5 = insufficient (AUC < 0.95), 5 < N < 12 = marginal, N ≥ 12 = reliable (AUC > 0.98). Real data estimated at 15–25+ cells for AUC > 0.95.

Open-source framework with correct methodology

Three bugs documented and fixed: calibration leakage (+0.28 AUC inflation), energy unit error (1000×), inconsistent baselines. All code is public.

Honest real-data validation

On 4 NASA cells, AUC = 0.46 — confirming the framework needs more data than a single public benchmark. Reproducible for any researcher to verify.

Limitations & Future Work

Current limitations

  • Only 4 cells, all 18,650 format under lab conditions
  • No deep learning (LSTM, TCN, Transformer) — CPU-only constraints
  • Simplified AR(1) price model
  • CALCE cross-chemistry evaluation incomplete

Future work

  • Validate scaling curve on real multi-cell datasets
  • Add cross-chemistry validation (LFP, NMC chemistries)
  • GPU-based deep learning benchmarks
  • Real price data instead of AR(1) simulation
